# BLOG DESIGN NOTE 11
## JLPT N1 학습 계획 및 운영 설계 / JLPT N1 学習計画・運用設計

작성 기준일 / 作成基準日: 2026-08-31  
목표 / 目標: 2027년 7월 JLPT N1 합격 / 2027年7月 JLPT N1 合格

## 1. 학습 목표 / 学習目標

- 목표 시험: 2027년 7월 JLPT N1
- 학습 시작일: 2026-09-01
- 2027년 공식 시험일 발표 전까지 2027-07-04를 임시 목표일로 사용하고 `target_date_is_tentative=1`로 표시한다.
- 사이트 집중 영역: 어휘, 문법, 독해
- 청해는 초기 사이트 구축 범위에서 제외한다.
- 신규 N1 어휘 목표: 약 3,000개
- 기본 신규 어휘량: 하루 20개
- 기본 어휘 문제: 하루 약 15문제
- 기본 문법: 하루 약 2개
- 기본 독해: 하루 1지문 이상
- 시험 직전에는 신규 학습보다 누적 복습과 실전 문제 비중을 높인다.

## 2. 기존 기능과의 관계 / 既存機能との関係

기존 `단어일람`과 `랜덤 퀴즈`는 유지한다.

```text
japanese_words (공통 원본 단어 DB)
        │
        ├─ 단어일람 / 単語一覧
        ├─ 랜덤 퀴즈 / ランダムクイズ
        └─ JLPT N1 학습 / JLPT N1 学習
```

JLPT용 단어를 별도의 단어 원본 테이블에 중복 저장하지 않는다. 동일 단어가 기존 DB에 존재하면 기존 레코드에 뜻·품사·예문 등을 병합하고 JLPT 커리큘럼만 연결한다.

## 3. JLPT 학습 홈 / JLPT 学習ホーム

경로:


- 최근 4주 학습 일정 및 완료 상태

일정 상태:

```text

```

## 4. 오늘의 학습 / 今日の学習

기본 학습 순서:

1. 이전에 밀린 필수 학습
2. 오늘 복습 예정 단어
3. 신규 N1 어휘 최대 20개
4. JLPT 형식 어휘 문제 약 15문제
5. N1 문법 약 2개 + 문법 문제
6. N1 독해 1지문 이상
7. 애매했던 단어 재확인

복습량이 과도한 날에는 신규 20개를 무조건 강제하지 않고 신규 배정량을 줄일 수 있도록 설계한다.

## 5. 어휘 학습 상태와 복습 / 語彙学習状態・復習

사용자에게 보이는 상태:

```text
미학습 / 未学習 = unlearned
애매함 / 曖昧 = uncertain
외움 / 暗記済 = mastered
```

내부에는 다음 정보를 별도로 저장한다.
- 최초 학습일
- 최근 학습일
- 복습 단계
- 다음 복습 예정일
- 정답 수 / 오답 수
- 최근 정답/오답 시각

기본 간격 반복:

```text
첫 학습
→ 1일
→ 3일
→ 7일
→ 14일
→ 30일
→ 60일
```

`mastered`를 계속 유지하면 복습 간격을 늘린다. `uncertain` 또는 `unlearned`로 평가하면 복습 단계를 0으로 낮추고 다음날 다시 복습한다.

## 6. 어휘 문제 / 語彙問題

단순 뜻 맞히기만 하지 않고 실제 JLPT 형식을 사용한다.

- 漢字読み
- 文脈規定
- 言い換え
- 用法

오늘 새로 배운 단어를 어휘 문제, 문법 예문, 독해 지문에서 자연스럽게 반복 노출한다. 독해에는 20개 전부를 억지로 사용하지 않고 문맥에 맞는 일부 단어만 활용한다.

## 7. 매일 데이터 추가 방식 / 毎日のデータ追加方式

ChatGPT에서 `오늘의 학습` 요청을 받으면 song-project의 현재 N1 커리큘럼과 기존 단어를 먼저 확인한다.

```text
song-project 기존 단어 확인
→ 이미 있는 단어 제외 또는 기존 레코드 재사용
→ 신규 N1 단어 20개 선정
→ 복습 예정 단어 확인
→ 어휘 문제 / 문법 / 독해 생성
→ 사이트용 데이터 준비
```

### 단어 Excel
기존 일본어 단어 Excel 등록 기능을 그대로 사용하되 선택 컬럼을 추가한다.

```text
jlpt_study_date
```

예:

```text
word | reading | meaning_ko | jlpt | jlpt_study_date
遂げる | とげる | 이루다|완수하다 | N1 | 2026-09-01
```

`jlpt=N1`이며 `jlpt_study_date`가 있으면:
1. 기존 단어 중복 검사
2. 기존 단어이면 병합, 없으면 신규 생성
3. 동일 단어를 JLPT용으로 다시 생성하지 않음
4. `N1_2027_JUL` 커리큘럼의 해당 학습일에 자동 연결

문법·독해·시험형 어휘 문제는 `japanese_jlpt_daily_contents`에 날짜별 JSON payload로 저장한다. 향후 별도 다중 시트 Excel 업로더로 확장 가능하다.

## 8. 주요 DB 구조 / 主要DB構造

기존 공통 데이터:

```text
japanese_words
japanese_word_examples
jlpt_levels
japanese_admin_word_learning_stats
```

JLPT N1 추가 데이터:

```text
japanese_jlpt_study_plans
japanese_jlpt_curriculum_words
japanese_jlpt_daily_sessions
japanese_jlpt_daily_words
japanese_jlpt_daily_contents
```

역할:
- `japanese_jlpt_study_plans`: 목표 시험과 일일 목표량
- `japanese_jlpt_curriculum_words`: N1 3,000단어 커리큘럼 순서와 도입 예정일
- `japanese_jlpt_daily_sessions`: 날짜별 학습량과 완료 상태
- `japanese_jlpt_daily_words`: 당일 복습/신규 단어 배정과 완료 상태
- `japanese_jlpt_daily_contents`: 어휘 문제, 문법, 문법 문제, 독해

## 9. 운영 전 실제 학습 데이터 보존 / 本番前の学習データ保存

실제 학습을 시작할 때는 **배포된 사이트가 사용하는 원격 Cloudflare D1 `song-project-db`**에 저장한다.

중요 원칙:
- Worker 코드를 새로 배포해도 원격 D1의 학습 데이터는 자동 삭제되지 않는다.
- `wrangler dev` 기본 로컬 D1은 원격 D1과 별개이므로 실제 장기 학습 기록용으로 사용하지 않는다.
- 로컬 개발 데이터는 `.wrangler/state`를 지우거나 환경을 바꾸면 사라질 수 있으며 운영 데이터로 간주하지 않는다.
- 스키마 변경은 버전 관리된 `migrations/`를 사용한다.
- **원격 DB migration 적용 후 Worker를 배포한다.**
- 기존 데이터를 삭제하는 `DROP`, 전체 초기화, 테스트 seed의 원격 적용 등 파괴적 작업은 별도 확인 없이 실행하지 않는다.
- 테스트 데이터는 로컬에서 우선 검증한다.

JLPT N1 기능 최초 운영 배포 순서:

```bash
npm run db:migrate:remote
npm run deploy
```

마이그레이션 `0030_jlpt_n1_study_plan.sql` 적용 후 실제 학습을 시작한다.
