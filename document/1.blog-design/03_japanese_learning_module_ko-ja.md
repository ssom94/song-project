# BLOG DESIGN NOTE 03
## 일본어 학습 모듈 설계 / 日本語学習モジュール設計

작성 기준일 / 作成基準日: 2026-08-29  
설계 상태 / 設計状態: 기능 요구사항 및 데이터 구조 초안

## 1. 목적 / 目的

### 한국어
개인 블로그 서비스 안에 JLPT 단어 학습 페이지를 추가한다. 관리자가 단어를 직접 등록하거나 향후 CSV/Excel로 대량 업로드하고, AI가 읽기/뜻/품사/JLPT 급수/학습 분류/예문을 추천한다. 관리자는 AI 제안을 확인하고 수정한 뒤 적용한다. 단어 상세 화면에서는 마우스, 터치, 펜을 이용한 직접 필기 연습을 지원한다.

### 日本語
個人ブログサービス内にJLPT単語学習ページを追加する。管理者が単語を直接登録し、将来的にはCSV/Excelによる一括登録にも対応する。AIは読み、意味、品詞、JLPTレベル、学習分類、例文を提案し、管理者が確認・修正したうえで適用する。単語詳細画面ではマウス、タッチ、ペンによる手書き練習を提供する。

## 2. 화면 구조 / 画面構成

### 관리자 / 管理
```text
/admin/japanese
├─ /words              단어 목록 / 単語一覧
├─ /words/new          단어 추가 / 単語追加
├─ /words/:id/edit     단어/예문 수정 / 単語・例文編集
├─ /levels             JLPT N1~N5 관리 / JLPT管理
├─ /parts-of-speech    품사 관리 / 品詞管理
├─ /categories         학습 분류 / 学習分類
└─ /ai-review          AI 제안 검토 / AI提案レビュー
```

### 학습 / 学習
```text
/japanese
├─ /words              필터/검색 단어 목록 / 検索・フィルタ
└─ /words/:id          단어 상세, 예문, 필기 / 詳細・例文・手書き
```

향후 `/japanese/quiz`, `/japanese/review`, `/japanese/favorites` 확장 가능.

## 3. 단어 데이터 / 単語データ

기본 저장 정보:

- 일본어 단어 표기 (`改善`, `取り組む`, `あらかじめ` 등)
- 히라가나 읽기
- 한국어 뜻
- 일본어 설명
- JLPT 급수 N1~N5
- 하나 이상의 품사
- 하나 이상의 학습 분류
- 관리자 메모
- AI 분석/검토 상태
- 생성/수정/삭제 시각

품사와 학습 분류는 여러 개 연결할 수 있도록 중간 테이블을 사용한다.

## 4. JLPT/품사/학습 분류 / JLPT・品詞・学習分類

### JLPT
N1, N2, N3, N4, N5를 기본 데이터로 둔다. 자료마다 급수 분류가 다를 수 있으므로 AI는 추천만 하고 관리자가 최종 확정한다.

### 품사
예:
- 名詞 / 명사
- サ変名詞
- 動詞 / 동사
- 五段動詞
- 一段動詞
- 不規則動詞
- い形容詞
- な形容詞
- 副詞 / 부사
- 接続詞 / 접속사
- 表現 / 표현

필요하면 부모-자식 품사 구조를 지원한다.

### 학습 분류
예:
- ビジネス / 비즈니스
- 開発 / 개발
- 日常生活 / 일상생활
- 面接 / 면접
- 感情 / 감정
- 移動 / 이동
- 食事 / 음식

학습 분류도 필요할 경우 계층형으로 확장 가능하다.

## 5. 예문 / 例文

한 단어에 여러 예문을 연결한다.

예:
```text
単語: 改善
読み: かいぜん
意味: 개선

例文:
業務の改善が必要です。
ぎょうむのかいぜんがひつようです。
업무 개선이 필요합니다.
```

예문별로 일본어 문장, 읽기, 한국어 번역, 문법/사용 메모, 수동/AI 생성 여부를 저장한다.

## 6. AI 분석 / AI分析

### 입력
관리자가 단어만 입력할 수 있다.

```text
単語: 改善
[AIで分析]
```

### AI 추천 후보
- `reading`: かいぜん
- `meaning_ko`: 개선, 개선함
- `meaning_ja`: より良い状態にすること
- JLPT 예상 급수
- 품사 후보
- 학습 분류 후보
- 복수 예문 + 한국어 번역

### 적용 원칙
```text
단어 입력
  ↓
AI 분석
  ↓
검토용 draft 저장
  ↓
관리자 확인/수정
  ↓
[적용]
  ↓
단어/예문/분류에 반영
```

AI가 직접 최종 데이터를 덮어쓰지 않는다. 어떤 AI/provider/model을 사용했는지와 제안 JSON, 적용/거절 상태를 남길 수 있게 한다.

향후 대량 등록을 지원한다.

최소 입력 예:

## 8. 필기 연습 UX / 手書き練習UX

단어 상세 페이지에 Canvas를 둔다.

```text
改善  かいぜん  개선

[        Canvas        ]

[되돌리기] [전체 지우기] [저장]
```

- 데스크톱: 마우스
- 모바일/태블릿: 손가락
- 펜 지원 기기: Stylus/Pointer Events
- 되돌리기, 전체 지우기, 저장
- 저장 후 최근 필기 목록 표시

## 9. 필기 저장 구조 / 手書き保存構造

### D1
`stroke_data`에 획별 좌표를 JSON으로 저장한다.

```json
[
  {
    "points": [
      {"x": 52, "y": 43, "t": 0},
      {"x": 54, "y": 48, "t": 16},
      {"x": 57, "y": 55, "t": 32}
    ]
  }
]
```

### R2
Canvas 완성 이미지를 PNG로 저장한다.

```text
japanese/handwriting/word-152/20260829-001.png
```

D1에는 `image_key`만 저장한다.

### 두 데이터를 모두 저장하는 이유
- PNG: 결과 미리보기/보관
- stroke JSON: 획 순서 재생, 애니메이션, 비교, 향후 판정

## 10. 필기 기능 단계 / 手書き機能フェーズ

### Phase 1 - 첫 구현
- 자유 필기
- 되돌리기/전체 삭제
- stroke JSON 저장
- PNG R2 저장
- 과거 필기 목록/보기

### Phase 2 - 확장
- 내가 쓴 획 순서 재생
- 이전 시도와 비교
- 연습 횟수/최근 연습일

### Phase 3 - 고급
- 기준 글자와 형태 비교
- 정확도 점수
- 획순 판정

Phase 3은 정식 획순 데이터와 추가 알고리즘/AI가 필요하므로 초기 구현 범위에서는 제외한다.

## 12. 보안/개인정보/비용 / セキュリティ・コスト

- AI API key는 클라이언트에 노출하지 않고 Worker secret으로 관리한다.
- AI 호출은 관리자 인증 후 서버에서만 수행한다.
- AI 대량 분석은 요청 개수/재시도 제한을 둔다.
- 필기 이미지 업로드 파일 크기와 Canvas 해상도를 제한한다.
- R2에는 랜덤/규칙화된 key를 사용하고 DB에는 key만 저장한다.
