## Cloudflare 기반 개인 블로그 / Cloudflareベース 個人ブログ

작성 기준일 / 作成基準日: 2026-08-29

## 1. 프로젝트 목표 / プロジェクト目標

### 한국어
Cloudflare를 중심으로 장기간 운영할 개인 개발 블로그를 구축한다. 글 작성은 관리자 1명만 가능하며, 일반 방문자는 회원가입이나 로그인 없이 글을 읽고 비회원 댓글을 작성할 수 있다. 사이트 기본 언어는 일본어이며, 상단 언어 선택으로 일본어/한국어 화면과 게시글 번역본을 전환한다. 설계 단계부터 이력 관리, 복구, 백업, 다국어, SEO 확장을 고려한다.

### 日本語
Cloudflareを中心に長期間運用できる個人開発ブログを構築する。記事作成は管理者1名のみとし、一般訪問者は会員登録やログインなしで記事閲覧と非会員コメント投稿ができる。サイトの既定言語は日本語とし、画面上部の言語選択で日本語/韓国語のUIと記事翻訳を切り替える。設計段階から履歴管理、復元、バックアップ、多言語、SEO拡張を考慮する。

## 2. 확정된 기능 요구사항 / 確定した機能要件

- 관리자 1명만 로그인하고 게시글을 작성/수정/삭제한다.  
  管理者1名のみがログインし、記事の作成・編集・削除を行う。
- 방문자는 회원가입/로그인 없이 글을 읽고 비회원 댓글을 작성한다.  
  訪問者は会員登録・ログインなしで記事閲覧と非会員コメント投稿ができる。
- 게시글에는 제목, 본문, 요약, 대표 이미지, 카테고리, 복수 태그, 작성일/수정일/공개일, 조회수가 있다.  
  記事にはタイトル、本文、要約、アイキャッチ画像、カテゴリ、複数タグ、作成日/更新日/公開日、閲覧数を持つ。
- 본문은 Markdown 기반으로 작성하며 코드 블록, 문법 하이라이팅, 코드 주석, 복사 버튼, NOTE/TIP/WARNING 메모 표시를 지원한다.  
  本文はMarkdownベースとし、コードブロック、シンタックスハイライト、コードコメント、コピー、NOTE/TIP/WARNING表示に対応する。
- 카테고리는 계층형이며 부모-자식 관계와 표시 순서를 관리한다.  
  カテゴリは階層型とし、親子関係と表示順を管理する。
- 태그는 비계층형 다대다 구조로 게시글에 여러 개 연결할 수 있다.  
  タグは非階層の多対多構造で、1記事に複数設定できる。
- 게시글/카테고리/태그는 물리 삭제 대신 Soft Delete를 기본으로 한다.  
  記事・カテゴリ・タグは物理削除ではなくSoft Deleteを基本とする。
- 관리자 주요 변경은 audit_logs에 기록하고, 게시글 내용은 revision 이력으로 이전 버전 확인/복구를 지원한다.  
  管理者の主要操作はaudit_logsに記録し、記事本文はrevision履歴で過去版の確認・復元を可能にする。
- 비회원 댓글의 실제 접속 IP를 저장하며 관리자에게만 표시한다.  
  非会員コメントの接続元IPを保存し、管理者だけが確認できる。
- 조회수는 동일 방문자의 동일 글 조회를 1시간 내 1회로 계산한다.  
  閲覧数は同一訪問者・同一記事について1時間以内は1回として数える。
- Cloudflare Turnstile/Rate Limit 등을 이용한 스팸 방지를 확장한다.  
  Cloudflare Turnstile/Rate Limit等でスパム対策を拡張する。

## 3. 다국어 정책 / 多言語ポリシー

- 기본 언어 / 既定言語: `ja` (日本語)
- 지원 언어 / 対応言語: `ja`, `ko`
- 향후 `en` 등 추가 가능한 구조로 설계한다.  
  将来 `en` 等を追加可能な構造とする。
- 사이트 UI의 메뉴/버튼/안내 문구는 선택 언어에 따라 변경한다.  
  サイトUIのメニュー・ボタン・案内文は選択言語に応じて切り替える。
- 게시글을 한국어로 작성하면 일본어 번역본을, 일본어로 작성하면 한국어 번역본을 생성해 DB에 저장한다.  
  韓国語で執筆した場合は日本語訳、日本語で執筆した場合は韓国語訳を生成してDBへ保存する。
- 번역은 페이지 요청 때마다 수행하지 않고 글 작성/수정 시 생성 후 저장한다.  
  翻訳はページ表示のたびに行わず、記事作成・更新時に生成して保存する。
- 자동 번역 결과는 관리자가 직접 수정하고 검토 완료 상태로 전환할 수 있다.  
  自動翻訳結果は管理者が編集し、レビュー完了状態へ変更できる。
- 카테고리/태그 표시명과 설명도 일본어/한국어 번역 데이터를 별도로 관리한다.  
  カテゴリ・タグの表示名と説明も日本語/韓国語の翻訳データを別管理する。
- 공개 URL은 언어 접두사를 사용한다: `/ja/...`, `/ko/...`. `/` 기본 접속은 일본어로 처리한다.  
  公開URLは言語プレフィックスを使う: `/ja/...`, `/ko/...`。`/` は日本語を既定とする。

## 4. 관리자 화면 / 管理画面

- `/admin` - 대시보드 / ダッシュボード
- `/admin/posts` - 게시글 목록 / 記事一覧
- `/admin/posts/new` - 새 글 작성 / 新規記事作成
- `/admin/posts/:id/edit` - 게시글 및 번역 수정 / 記事・翻訳編集
- `/admin/comments` - 댓글 관리 + IP 확인 / コメント管理 + IP確認
- `/admin/categories` - 계층형 카테고리 관리 / 階層カテゴリ管理
- `/admin/tags` - 태그 관리 / タグ管理
- `/admin/history` - 게시글/카테고리/태그 등 전체 변경 이력 / 全体変更履歴

## 5. 방문자 화면 / 公開画面

- `/` - 기본 일본어 홈으로 연결 / 日本語ホームを既定表示
- `/ja/`, `/ko/` - 언어별 홈 / 言語別ホーム
- `/{lang}/posts` - 게시글 목록 / 記事一覧
- `/{lang}/posts/:slug` - 게시글 상세 + 댓글 / 記事詳細 + コメント
- `/{lang}/categories/:slug` - 카테고리별 게시글 / カテゴリ別記事
- `/{lang}/tags/:slug` - 태그별 게시글 / タグ別記事
- `/{lang}/search` - 검색 결과 / 検索結果

## 6. Cloudflare 시스템 구조 / Cloudflareシステム構成

- Cloudflare Workers: Frontend + API + 언어 라우팅 / Frontend + API + 言語ルーティング
- Cloudflare D1: 게시글, 번역, 댓글, 카테고리, 태그, revision, audit 등 구조화 데이터
- Cloudflare R2: 대표 이미지 및 본문 이미지
- GitHub: 소스코드와 설계 문서 버전 관리
- Cloudflare Builds: `main` push 시 자동 배포, `document/**` 변경은 배포 제외
- 향후 번역 서비스/API는 글 저장 시 호출하도록 연결하며 구체 공급자는 별도 결정

## 7. 확정 데이터 모델 후보 / 確定データモデル候補

- `admins` - 관리자 인증 / 管理者認証
- `posts` - 언어와 무관한 게시글 공통 정보 / 言語非依存の記事共通情報
- `post_translations` - 일본어/한국어 제목·본문·slug·요약 / 記事翻訳
- `post_revisions` - 게시글/번역 버전 이력 / 記事・翻訳バージョン履歴
- `categories` - 계층/순서 등 공통 카테고리 정보 / カテゴリ共通情報
- `category_translations` - 카테고리명·설명·slug 번역 / カテゴリ翻訳
- `tags` - 태그 공통 정보 / タグ共通情報
- `tag_translations` - 태그명·설명·slug 번역 / タグ翻訳
- `post_tags` - 게시글-태그 다대다 연결 / 記事-タグ多対多
- `comments` - 비회원 댓글, 비밀번호 해시, IP / 非会員コメント、PWハッシュ、IP
- `audit_logs` - 관리자 작업 감사 이력 / 管理者操作監査履歴

## 8. 삭제·이력·복구 원칙 / 削除・履歴・復元方針

- 게시글, 카테고리, 태그는 `deleted_at`을 사용하는 Soft Delete를 기본으로 한다.
- 삭제 전 카테고리/태그 관계는 가능한 범위에서 유지하여 과거 상태를 확인할 수 있게 한다.
- 하위 카테고리가 있는 상위 카테고리는 즉시 삭제하지 못하게 하고, 하위 항목 이동/삭제 후 처리한다.
- 카테고리 이동 시 자기 자신 또는 자신의 하위 카테고리를 부모로 설정하는 순환 구조를 금지한다.
- 게시글 수정 시 revision을 남겨 이전 버전 보기/현재 버전 비교/복구 기능을 가능하게 한다.
- create/update/delete/restore/publish 등 주요 작업은 audit_logs에 before/after 데이터를 남긴다.
- revision과 audit은 복구/추적 기능이며, D1/R2 전체 백업은 별도 운영 백업 정책으로 구성한다.

## 9. 개인정보 및 조회수 / 個人情報・閲覧数

- 댓글 IP는 원본을 저장하되 관리자에게만 노출하고 공개 화면에는 표시하지 않는다.
- 실제 운영 전 개인정보 안내와 IP 보관 기간을 정한다.
- 조회수 중복 판정은 동일 방문자 + 동일 게시글을 1시간 내 1회로 처리한다.
- 조회수 판정을 위해 원본 IP를 장기간 누적하기보다 IP/User-Agent 등을 서버 비밀값과 함께 해시하여 단기 판정에 사용하는 방식을 우선 검토한다.

## 11. Git 문서 관리 규칙 / Gitでの設計資料管理ルール

```text
song-project/
└─ document/
   └─ 1.blog-design/
      ├─ 01_requirements_and_plan_ko-ja.md
      ├─ 01_requirements_and_plan_ko-ja.pdf
      ├─ 02_database_design_ko-ja.md
      ├─ 02_database_design_ko-ja.pdf
      └─ ...
```

Markdown을 수정 가능한 원본으로, PDF를 보관/공유용 결과물로 함께 Git에 저장한다. `document/**` 변경은 Cloudflare 자동 배포 대상에서 제외한다.
